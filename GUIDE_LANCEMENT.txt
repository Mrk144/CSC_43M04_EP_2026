--------------------------------------------------------------------------------
0. RAPPELS IMPORTANTS
--------------------------------------------------------------------------------

  • num_classes : 33 (configs/config.yaml).

  • dataset.num_frames : nombre de JPEG lus par clip sur le disque (défaut 4).

  • model.num_frames : longueur temporelle INTERNE au modèle (interpolation
    linéaire dans le forward) — Track A souvent 7, Track B souvent 16 (InternVideo2: 8).

  • Checkpoint sauvé : training.checkpoint_path (défaut "best_model.pt"),
    relatif au répertoire du run Hydra. Après un train simple :
      src/outputs/YYYY-MM-DD_HH-MM-SS/best_model.pt

  • Pour forcer un dossier de sortie (recommandé) :
      python train.py experiment=... hydra.run.dir=/abs/run/mon_experience

  • Normalisation : si model.pretrained=true, build_transforms utilise les stats
    ImageNet (cohérent VideoMAE, foundation models, ResNet ImageNet).

  • Variable shell utile pour les exemples ci-dessous :
      export CKPT=/abs/chemin/vers/best_model.pt

2.1 baseline_from_scratch — recommandations

Le YAML ne fixe que le modèle ; l’entraînement par défaut vient de
configs/train/default.yaml (batch 8, lr 1e-4, 5 epochs). Pour un entraînement
sérieux, alignez-vous sur track_a_best :

  python train.py experiment=baseline_from_scratch \
    training.batch_size=64 training.lr=3e-4 training.epochs=40 \
    training.warmup_epochs=3 training.num_workers=12 \
    training.optimizer.name=adamw training.optimizer.weight_decay=0.05 \
    training.loss.name=cross_entropy training.loss.label_smoothing=0.1


2.2 Autres modèles « from scratch » sans expérience dédiée

Hydra peut composer model=cnn_lstm, cnn_lstm_improved en remplaçant le groupe
model, mais l’experiment baseline_from_scratch force cnn_baseline. Utilisez
une chaîne d’overrides qui remplace bien le modèle, ou copiez un yaml.

  Exemple (CNN + BiLSTM from scratch, 7 frames internes, recette proche Track A) :

  python train.py \
    model.name=cnn_lstm model.pretrained=false model.num_frames=7 \
    model.lstm_hidden_size=256 \
    training.batch_size=32 training.lr=3e-4 training.epochs=40 \
    training.warmup_epochs=3 training.num_workers=12 \
    training.optimizer.name=adamw training.optimizer.weight_decay=0.05 \
    training.loss.label_smoothing=0.1

  Variante « improved » (dropout + GELU) :

  python train.py \
    model.name=cnn_lstm_improved model.pretrained=false model.num_frames=7 \
    model.lstm_hidden_size=256 model.dropout=0.5 \
    training.batch_size=32 training.lr=3e-4 training.epochs=40 \
    training.warmup_epochs=3 training.num_workers=12 \
    training.optimizer.name=adamw training.optimizer.weight_decay=0.05 \
    training.loss.label_smoothing=0.1

VRAM (ordre de grandeur) : two-stream et cnn_transformer plus lourds que
tsm_resnet seul ; réduisez batch_size si OOM.

3.1 Une phase — fine-tune direct (backbone + tête)

  experiment                | modèle              | prét. | T int. | batch | lr    | epochs | warmup

3.3 Deux phases (geler backbone → finetune complet)

Script depuis la RACINE du dépôt :

  chmod +x scripts/train_two_phase.sh

  ./scripts/train_two_phase.sh videomae
  ./scripts/train_two_phase.sh videomae_large
  ./scripts/train_two_phase.sh vjepa2
  ./scripts/train_two_phase.sh internvideo2
  ./scripts/train_two_phase.sh x3d

Équivalent VideoMAE seul :

  chmod +x scripts/train_videomae_two_phase.sh
  ./scripts/train_videomae_two_phase.sh

Overrides pour les DEUX phases (ex. moins de VRAM) :

  TRAIN_EXTRA_ARGS="training.batch_size=4 training.device=cuda" ./scripts/train_two_phase.sh vjepa2


TABLE récapitulative phase 1 (head) / phase 2 (finetune) :

  tag            | phase 1 experiment              | bs  | lr    | ep | phase 2 experiment               | bs | lr    | ep
  ---------------+---------------------------------+-----+-------+----+----------------------------------+----+-------+----
  videomae       | track_b_videomae_head           | 8   | 1e-3  | 5  | track_b_videomae_finetune        | 8  | 2e-5  | 10
  videomae_large | track_b_videomae_large_head     | 4   | 1e-3  | 5  | track_b_videomae_large_finetune  | 2  | 1e-5  | 10
  vjepa2         | track_b_vjepa2_head             | 8   | 1e-3  | 5  | track_b_vjepa2_finetune          | 4  | 1e-5  | 10
  internvideo2   | track_b_internvideo2_head       | 8   | 1e-3  | 5  | track_b_internvideo2_finetune    | 4  | 1e-5  | 10
  x3d            | track_b_x3d_head                | 16  | 1e-3  | 5  | track_b_x3d_finetune             | 8  | 5e-5  | 15

Phase 2 nécessite le checkpoint phase 1 : le script place resume_from automatiquement.
Manuel phase 2 :

  python train.py experiment=track_b_videomae_finetune \
    training.resume_from=/abs/phase1/best_model.pt \
    hydra.run.dir=/abs/run/videomae_phase2

Tous les yaml finetune ont training.resume_model_only: true (recharge uniquement
les poids du réseau, pas l’optimiseur de la phase 1).

4. ESSAYER UN MODÈLE — ÉVALUATION (validation complète)
--------------------------------------------------------------------------------

Toujours depuis src/. Le checkpoint doit être le best_model.pt du bon run.

  python evaluate.py training.checkpoint_path=$CKPT

Paramètres souvent utiles :

  python evaluate.py \
    training.checkpoint_path=$CKPT \
    training.batch_size=16 \
    training.device=cuda \
    dataset.val_dir=/abs/val

Les métriques affichées (top-1, top-5) utilisent le même prétraitement que
l’entraînement : le flag pretrained du checkpoint pilote ImageNet norm vs [0.5].

  python create_submission.py training.checkpoint_path=$CKPT

  python create_submission.py \

--------------------------------------------------------------------------------
6. PRÉDICTIONS POUR ENSEMBLE — predict_softmax.py
--------------------------------------------------------------------------------

Par modèle entraîné, génère val.npz + test.npz (alignement des noms de vidéos
obligatoire pour ensemble.py).

  python predict_softmax.py training.checkpoint_path=$CKPT

Dossier de sortie explicite (recommandé si plusieurs modèles) :

  python predict_softmax.py \
    training.checkpoint_path=$CKPT \
    predict.output_dir=/abs/preds/nom_du_modele

Contenu : val.npz (softmax, labels, val_accuracy), test.npz (softmax).


--------------------------------------------------------------------------------
7. ENSEMBLE — soft voting (pas un MoE entraîné)
--------------------------------------------------------------------------------

  1) predict_softmax pour chaque checkpoint
  2) Éditer src/configs/ensemble/default.yaml : val_npz, test_npz par modèle
  3) Lancer :

  python ensemble.py +ensemble=default

Méthodes :

  python ensemble.py +ensemble=default ensemble.method=mean_softmax
  python ensemble.py +ensemble=default ensemble.method=weighted_softmax ensemble.weights=[0.6,0.4]
  python ensemble.py +ensemble=default ensemble.method=weighted_softmax ensemble.weights=auto
  python ensemble.py +ensemble=default ensemble.method=temperature_then_mean \
    ensemble.output_csv=/abs/submission_ensemble.csv


--------------------------------------------------------------------------------
8. VRAM (~20 Go) — PARAMÈTRES À AJUSTER
--------------------------------------------------------------------------------

  • Réduire training.batch_size (phase 2 VideoMAE large : déjà 2).
  • foundation models : batch 4 → 2 → 1
  • track_a_best batch 64 → 32 ou 16
  • model.variant plus léger (VideoMAE base vs large ; x3d_xs vs x3d_m)
  • dataset.max_samples pour valider le pipeline sans saturer la mémoire
